# 请求日志

管理员在「请求日志」按状态、渠道、模型、账号、任务类型和时间筛选。搜索支持请求 ID、任务 ID、会话 ID、摘要和已脱敏请求内容。筛选覆盖整个日志文件，结果每页 20 条；批量删除仅针对当前页选中的记录。

列表展示请求模型、实际执行模型、账号与渠道、最终状态、耗时和产出/请求数量。详情分为调用概览、耗时与用量、错误信息、输入素材摘要、上传记录、执行过程、生成结果和原始 JSON。点击账号进入号池并自动搜索对应邮箱或稳定 ID。

## 字段口径

- `requested_model`：调用请求中的模型。`actual_model` 只来自执行节点，`actual_model_source=upstream_request` 表示实际发送给上游的模型，并不保证上游内部没有再次路由；不以兼容响应的模型回显代替执行证据。
- `request_id`、`task_id`：调用和生成任务标识；历史记录缺少时不补造。
- `requested_count`、`output_count`：请求数量和有记录的产出数量。零与未知分别显示；`partial_success` 或已知数量不足时显示部分成功。
- `queue_duration_ms`、`execution_duration_ms`：任务时间戳对应的墙钟时长，多子任务并行时不累加。`first_token_ms` 从调用开始计至第一个非空文本增量；`usage` 使用已有响应用量。
- `attempts`：有记录的尝试过程。旧数据只有尝试账号集合时，不推断顺序或每次失败所属账号。
- 每次生成尝试独立记录模型和素材上传证据，换号及同账号重新提交均不继承上一轮；继续读取原生成结果时保留原证据。
- 批量图片任务的实际模型只有在所有子任务均已记录且一致时才合并展示；不同模型或部分未知时，查看各子任务的执行过程。
- `quota_snapshot`：有更新时间的账号缓存额度快照，不是即时查询，也不把本项目 API Key 的限额当作上游账号额度。
- 未采集或上游不提供的字段显示「未知」，不回填历史记录，不用零代替未知。

## 素材摘要

`request_params` 中的图片、文件及 base64 内容仍省略，仅保留可取得的格式、尺寸、字节数、SHA-256 和解码状态。同一字节内容的裸 base64 与 data URI 指纹一致。摘要处理共享 20 MiB 预算，超限标记 `omitted_too_large`；不读取上传文件流，不为日志下载外部 URL。

`input_uploads` 记录执行路径取得的上传确认、失败阶段及实际上传字节指纹。输入经过压缩或格式转换后，输入指纹与上传指纹可能不同。解码成功不等于上传成功；没有确认记录时显示未知。

创作页图片任务从任务已有的私有输入文件生成摘要，不额外保存原文；输入文件已清理或损坏时，其余日志仍正常记录。

## 查询接口

`GET /api/logs` 保留管理员鉴权以及 `type`、`start_date`、`end_date`，新增 `status`、`channel`、`model`、`account`、`task_type`、`q`、`page`、`page_size`。

响应：`{ "items": [], "total": 0, "page": 1, "page_size": 20 }`。页码从 1 开始，页大小为 1–100。日期按 UTC+8 筛选；模型和账号支持部分匹配。原有日志无需迁移，任务库新增诊断列由启动时兼容补充。
