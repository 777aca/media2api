# 账号在途状态与飞书配额提醒

号池管理会高亮正在处理请求的账号。ChatGPT / Codex 显示“生成中 · N 张”，Grok 显示“处理中 · N 个请求”（包括文本及媒体请求）。页面在前台且没有导入、编辑或批量操作时，每 5 秒读取本地在途计数，不触发上游额度同步或模型目录同步。

## 配置飞书机器人

在“设置 → 号池维护 → 飞书配额提醒”填写飞书群自定义机器人的 Webhook；若开启签名校验，同时填写签名密钥。可先点击“测试推送”，确认群内收到测试消息后启用并保存。测试不会保存或启用通知。机器人启用关键词校验时，添加 `media2api`。协议依据[飞书自定义机器人使用指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。

- 号池总剩余配额阈值可自定义，范围 0–10000，默认 3；同类额度先跨账号相加，总剩余小于等于阈值时提醒，0 表示只提醒已知总额度耗尽。例如两个账号各剩 2 次，总计 4 次，阈值为 3 时不提醒；总剩余降为 3 次时提醒。
- ChatGPT 图片、Grok 快速、自动、图片、视频等各类次数分别汇总，不跨渠道或用途相加。Grok 周额度计算 `100 × 各账号剩余额度之和 / 各账号总额度之和`，使用汇总后的剩余百分比比较阈值，不累加各账号百分比。
- 重复提醒间隔可设为 15–10080 分钟，默认 60 分钟。
- Webhook 与密钥不回显；留空保存会保留原值，可单独清除签名密钥。

服务每 30 秒检查本地最新配额快照，页面关闭后仍运行。ChatGPT 图片额度必须存在上游 `image_gen.remaining` 证据，再使用当前本地扣减后的 `quota`。Grok 使用最近同步的各项额度。未知、异常、禁用账号和已超过重置时间的旧配额不计入；目前无明确配额数据的 Codex 账号不计入。没有任何已知账号的类别不触发零额度提醒。通知明确显示“已知总剩余”及参与汇总的账号数，未计入的未知配额可能影响实际总量。通知不主动向上游查询，快照过旧时请在号池管理中同步额度。

同批合并不足的额度类别，去重按号池类别进行；替换单个账号但总额度没有变化，不会额外提醒。总配额恢复后会重新判定；从 0 部分恢复再变为 0，也会重新提醒耗尽。状态保存在 `data/quota-alert-state.json`，重启后保留去重记录。升级到汇总规则后，旧版按账号的去重记录会在首次扫描时被替换，符合条件的类别发送首次汇总通知。发送失败 5 分钟后重试，界面可刷新查看失败状态。消息只含额度类别、已知总剩余及参与汇总的账号数，不含邮箱、账号令牌、Webhook 或密钥；时间使用 UTC+8。

这是快照检查：两次扫描之间已删除的账号、未被快照捕获的短暂配额变化无法提醒。部署时保留 `data/` 以维持去重状态；同一号池只运行一个通知调度实例，避免多个独立进程重复推送。

## 管理接口

以下接口均需管理员 Bearer Key：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/quota-alerts` | 脱敏配置与最近自动发送状态 |
| `POST /api/quota-alerts` | 保存通知配置 |
| `POST /api/quota-alerts/test` | 使用提交的草稿配置发测试消息，不修改保存配置 |

配置字段为 `enabled`、`webhook_url`、`secret`、`threshold`、`repeat_minutes`。保存和测试均可用空字符串保留已有凭据；`clear_secret: true` 清除签名密钥。返回包含 `has_webhook`、`has_secret`，凭据字段为空。配置不合法返回 400，机器人未确认成功返回 502。
