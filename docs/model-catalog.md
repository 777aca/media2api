# 图片模型目录与账号权限

账号页和设置页的“可用图片模型”继续只提供图片型号，图片目录根据本地账号池即时构建。`GET /v1/models` 合并图片入口和 ChatGPT / Codex 文本模型；文本目录由账号级模型服务按需同步并缓存，失败时保留已有缓存，图片入口仍可使用。

## 展示范围

| 型号 | 展示条件 | 标记 |
| --- | --- | --- |
| `gpt-image-2` | 存在活跃账号 | 项目入口 |
| `gpt-image-2.5-flare`、`gpt-image-2.5-sunburst` | 存在活跃账号 | 图片接口 |
| `codex-gpt-image-2` | 存在 Codex 来源的 Plus、Team 或 Pro 账号 | 项目入口 |
| `plus-codex-gpt-image-2`、`team-codex-gpt-image-2`、`pro-codex-gpt-image-2` | 存在对应套餐的 Codex 账号 | 项目入口 |

禁用、异常、已删除或缺少 Token 的账号不贡献目录。相同型号去重，账号新增、删除或状态变化在下次读取时立即生效。

“图片接口”表示已实现该独立图片通道；“项目入口”表示项目提供的图片兼容路由。它们均不代表已通过一次上游调用验证账号权限或额度。Flare、Sunburst 不由普通文本模型目录返回，刷新目录不会自动发现尚未接入的新图片型号。详见[图片 2.5 接入](image-models-2.5.md)。

## 刷新方式

页面打开时加载图片目录，页面可见时每分钟重新读取本地账号状态。“刷新目录”立即重新读取；这些操作不会向上游发送模型目录请求，也不会进行图片生成或刷新账号凭据。`GET /v1/models` 首次读取或文本缓存到期时会同步上游文本目录；账号信息与额度继续使用账号页已有刷新功能。

图片目录不使用文本模型的五分钟缓存，因此不会在禁用或删除账号后保留旧入口。页面请求失败时保留上次显示的目录并提示失败；首次失败显示原因，不误报为没有账号。最近更新时间表示本地目录读取成功的时间。

## 接口

| 接口 | 权限 | 返回与行为 |
| --- | --- | --- |
| `GET /v1/models` | 有效调用密钥 | 文本模型与图片入口，保留 OpenAI 的 `object`、`data` 格式。 |
| `GET /api/image-models` | 有效调用密钥 | 图片工作台专用的本地图片目录，不触发文本目录同步。 |
| `GET /api/models` | 管理员 | 图片目录、入口标记及本地刷新状态。 |
| `POST /api/models/sync` | 管理员 | 保留原路径兼容调用方，立即重新构建本地图片目录。 |

管理员记录保留 `source: compatibility`；独立图片接口带 `entry_kind: image_api`。公共 `/v1/models` 不返回这些管理字段。`sync` 保留原字段形状，`source_count` 与 `successful_sources` 现在表示贡献目录的活跃账号数量，`last_attempt_at` 与 `last_success_at` 表示本次本地读取时间。没有活跃账号时，管理端图片目录为空，账号数为零。

图片请求沿用原有模型路由、账号配额与并发调度。文本调用仍可显式指定型号；文本权限目录可由公共模型列表或文本请求触发，不会由图片目录或页面轮询触发。账号内部 `pool_account_id` 及 Token 更新后的关联方式保持兼容。

## 验证

使用项目虚拟环境运行 `scripts/run_model_catalog_tests.py`。该入口复制源码和示例配置到临时目录，封锁出站网络，覆盖图片目录、账号状态、接口格式、图片协议及既有文本路由回归，不读取真实账号。结果写入 `logs/model-catalog-tests.log`。

前端运行 `bun test src`、`bunx tsc --noEmit --incremental false` 和 `bun run build`。本地验证检查图片工作台、账号页和设置页的图片入口一致，并确认刷新图片目录不会请求上游文本模型接口。
